# 课堂总结 · Classnote

> 在手机或电脑上，把课程记录整理成可查找、可回顾的结构化笔记。

**[打开应用 →](https://ndshuge.github.io/ndshuge-classnote/)**

![Classnote 课堂总结真实网页截图](docs/screenshots/classnote.png)

## 1 分钟上手

1. **[打开 Classnote](https://ndshuge.github.io/ndshuge-classnote/)**，新建课程并填写课堂日期。
2. 将已有课堂记录分段粘贴到编辑区，手动整理重点与待办事项。
3. 需要 AI 总结时，再按设置页面提示连接自己获授权的 AI 服务；不连接 AI 也可使用基础笔记功能。
4. 学习记录涉及重要资料时，**先导出备份再清理浏览器数据或切换设备**。

<sub>已有的云同步与跨设备删除机制存在已知边界，详见下文「隐私与数据」和「数据可靠性与备份」；不要将应用视为唯一备份。</sub>

## 能做什么？

- **课程管理**：按课程整理记录，结合日历查看学习内容。
- **AI 辅助总结（可选）**：将已有的课堂转写文本粘贴进应用，按提示配置自己的 AI 服务后生成结构化总结。
- **离线基础功能**：不填写 AI Key 也能管理课程、待办、笔记与导出备份。
- **跨设备同步（可选）**：登录后使用应用提供的同步能力；游客数据保存在当前浏览器。
- **移动端体验**：响应式页面、深浅色主题、适配手机操作。

## 快速开始

1. 打开 [在线应用](https://ndshuge.github.io/ndshuge-classnote/)。
2. 按首次使用引导添加课程；不想接入 AI 可直接跳过密钥设置。
3. 需要总结课堂内容时，先用手机或电脑的录音/转写软件取得文字，再将文字粘贴到页面中。
4. 如要生成 AI 总结，请自行选择服务商、配置账号及 API Key。
5. 定期导出备份，尤其是在只使用游客模式时。

**注意：网页本身并不替代系统录音软件。** 录音与语音转文字通常需要先在系统或其他工具中完成。

## 隐私与数据

- 使用 AI 功能时，你提交的课堂文本会发送给所选 AI 服务商；请遵守学校、老师与同学的隐私要求。
- 账号、同步、密钥与本地缓存的安全性依赖应用实现和浏览器环境。不要在公共或不可信设备上保存密钥。
- 不要上传未经授权的课堂录音、含有他人个人信息的材料或保密资料。
- 若使用游客模式，清理浏览器站点数据可能导致本地记录丢失，请提前导出。

## 本地运行与结构

该仓库目前以 `index.html` 为前端入口，直接打开即可访问大部分界面。如果浏览器对 `file://` 存储或网络请求有限制，请启动一个本地静态服务器：

```bash
python -m http.server 8000
```

然后在浏览器中打开 `http://localhost:8000/`。部署使用 GitHub Pages。

## 数据可靠性与备份（2026-10-10）

- **转写草稿自动恢复**：输入或粘贴课堂转写后，浏览器短暂延迟保存本机草稿；刷新页面可以继续编辑。草稿不纳入 JSON 备份，也不等于云端备份。
- **备份导出**：设置 → 导出备份。JSON 包含笔记、课程、待办状态和学期起点；不包含 AI Key、Supabase 登录令牌、密码和未归档草稿。备份本身可能含有课堂原文，请保管好文件。
- **备份恢复**：设置 → 导入备份。兼容旧版 v3 包和历史记录数组；先检查格式、预览变更数量并确认，再按笔记 ID 合并。保留现有记录、课程及已完成事项。
- **失败提示**：本地空间不足或存储受限时，不再把未写入的笔记误报为已经归档。
- **展示安全**：待办文本与 Markdown 链接会进行 HTML 属性转义。

### 已知边界

- 清除浏览器网站数据、使用无痕模式或换设备，都可能丢失未导出的本地笔记和草稿；建议定期手动导出备份。
- 云同步依赖线上 Supabase 权限和连接状态；本轮未更改生产数据库，也未完成线上 RLS 安全验收。
- 当前跨设备同步采用并集合并，其他设备的旧记录可能使已删除的笔记重新出现。跨设备删除大量数据前，请先备份。
- 导出的课堂文字可能涉及老师和同学隐私，切勿把原文备份直接上传公开 Issue。
